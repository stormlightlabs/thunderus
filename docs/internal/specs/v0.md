# v0 and Alpha Spec

The user-facing portions of this spec have moved into the book.

## Remaining Internal Scope

The following work is still planning/spec material and should not be presented
as completed user-facing documentation yet:

- Session persistence.
- Safe file operations.
- Config file support.
- Non-TUI inspect and export commands.
- v1 compatibility guarantees.

## Prompt Improvements And Fragments

v0 should make prompt assembly explicit and testable without adding new modes.

Required:

- Split the current prompt bundle into small fragments.
- Keep base identity, communication style, action safety, project context,
  tool catalog, transcript context, and web/source guidance as separate pieces.
- Put tool-specific behavior in the corresponding tool description instead of
  the global prompt when possible.
- Add snapshot coverage for the assembled prompt and for important fragment
  combinations.
- Add a prompt-debug path that can show the assembled prompt without contacting
  a provider.

Non-goals:

- No plan mode.
- No task management or todo system.
- No multi-agent orchestration.
- No LSP integration in v0.

## Shell And Process Manager

v0 should include a bounded shell/process manager because real coding workflows
need build, test, format, and local inspection commands.

Required behavior:

- Run commands in the workspace by default.
- Show command, working directory, status, stdout, stderr, and elapsed time.
- Support timeouts and cancellation.
- Stream output without blocking the TUI.
- Keep a small process registry for active commands.
- Track long-lived background processes separately from one-shot commands.
- Record command start, output summary, exit status, timeout, and cancellation
  as structured transcript/tool events.
- Prefer narrower built-in tools for file search, file reads, edits, and URL
  reads when they fit.

Safety boundaries:

- Commands that write outside the workspace require explicit user approval.
- Commands that access the network follow the same approval path as other
  network-capable tools.
- Destructive commands require explicit user approval.
- Shell-based attempts to bypass denied file or network operations must be
  detected and blocked where deterministic policy can identify them.
- Secrets are redacted from displayed and recorded output where deterministic
  redaction is possible.
- The process manager should not become a package manager, scheduler,
  general-purpose daemon supervisor, or remote shell.

## `read_url`

v0 should add a narrow read-only URL tool.

Required behavior:

- Accept public `http` and `https` URLs.
- Reject private, loopback, link-local, and unsupported schemes.
- Follow redirects only within the configured limit.
- Enforce request timeout, response size cap, and content-type handling.
- Return final URL, status, title when available, readable text, truncation
  state, and diagnostics.
- Record each call as a structured transcript/tool event.
- Reuse existing search/extraction or Lectito-style readable extraction where
  it already fits.

The tool should not execute page scripts, submit forms, mutate remote state, or
read local files through URL-like paths.

## Internal Release Notes

Alpha can keep changing CLI, config, and session contracts. v1 should define the
supported public surface for CLI flags, config keys, environment variables,
session/event formats, tool behavior, and documented workflows.
