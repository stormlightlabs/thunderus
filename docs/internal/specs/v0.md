# v0 and Alpha Spec

`thndrs` starts as a minimal Rust + Ratatui coding harness. v0 proves the UI,
state, transcript, fake agent stream, and tests. Alpha turns that harness into a
usable coding assistant with Umans, visible context, read-only repository tools,
session persistence, search, and guarded file edits.

## Release Goals

### fake/v0

Goal: prove the Ratatui shell, input loop, transcript rendering, event model,
fake stream, tool-event display, and test strategy.

Required:

- `thndrs` launches a full-screen TUI by default.
- Clap parses the first flat CLI shape.
- User can type, submit, clear, and quit.
- Fake agent stream emits assistant, reasoning, tool, done, and error states.
- Layout survives normal and narrow terminal sizes.
- Snapshot and unit tests cover stable fake states.

Not required:

- Network calls.
- Real model/provider.
- File writes.
- Session persistence.
- Config files.
- Packaging beyond `cargo run`.

### alpha

Goal: become useful on a real repository while CLI/config/session contracts can
still change.

Required:

- Umans provider works with `umans-coder` and `umans-glm-5.2`.
- `UMANS_API_KEY` is the only secret path.
- Native Umans web search can be enabled/disabled.
- Root `AGENTS.md` and explicit context sources are visible in the transcript.
- Sessions persist as append-only JSONL and resume.
- Read-only local tools exist for path discovery, file reading, and text search.
- Guarded file-edit tools exist for create file, exact-range replace, and
  unified patch apply.
- Stop/cancel and provider errors recover to a usable prompt.
- Local Lectito search/extraction is available as a fallback or inspection path.

Allowed instability:

- Session JSONL fields can change.
- CLI flags can still be renamed.
- Config file shape is optional or unstable.
- Live provider smoke tests can remain manual/ignored.

## Out Of Scope

- MCP.
- Sub-agents.
- Built-in plan mode or todo manager.
- Multi-provider abstraction before a second provider exists.
- Background process manager.
- Server/client detach and reattach.
- PTY panes or terminal multiplexing.
- Plugins, socket API, or external control protocol.
- Multi-line editor with full shell/editor keybindings.

## CLI Entrypoint

Use `clap` derive syntax and keep the entrypoint flat. The binary launches the
TUI when run with no subcommand.

```rust
#[derive(clap::Parser, Debug)]
#[command(version, about = "Minimal Rust + Ratatui coding harness")]
pub struct Cli {
    #[arg(long, default_value = ".")]
    pub cwd: std::path::PathBuf,

    #[arg(long, default_value = "umans-coder")]
    pub model: String,

    #[arg(long, value_enum, default_value_t = WebSearchMode::Native)]
    pub websearch: WebSearchMode,

    #[arg(long, default_value_t = 100)]
    pub tick_rate_ms: u64,

    #[arg(long)]
    pub no_alt_screen: bool,

    #[arg(long)]
    pub print_prompt: bool,
}
```

Rules:

- No subcommands before alpha.
- No `--provider` while Umans is the only provider.
- `--cwd` controls context loading/display, not process-global `chdir`, unless
  a later feature requires it.
- `--model` accepts `umans-coder` and `umans-glm-5.2` first.
- `--websearch` maps directly to `X-Umans-Websearch-Provider`.
- `--print-prompt` prints the assembled prompt bundle/lowered provider messages
  with secrets redacted and exits without calling the provider.
- Keep secrets out of CLI flags. Use `UMANS_API_KEY`.

## UI Contract

The first screen is the product. No splash screen.

```text
+----------------------+-----------------------------------------------+
| thndrs               | Transcript                                    |
|                      |                                               |
| Sessions             |  user     explain this repo                   |
| > scratch            |  assistant streaming response...              |
|                      |  tool     read Cargo.toml                     |
| Status               |                                               |
| idle                 |                                               |
|                      |                                               |
|                      | --------------------------------------------- |
|                      | > prompt text                                 |
|                      | model: fake-agent        cwd: /repo           |
+----------------------+-----------------------------------------------+
```

Layout rules:

- Sidebar width: fixed 22 columns for v0.
- Main area: remaining width.
- Footer: one line.
- Prompt: two lines when model/status label is visible; otherwise one line.
- Transcript: fills remaining height and shows newest entries.
- Hide sidebar at narrow widths before wrapping critical prompt/status text.

Gridland-derived rules:

- Treat the shell as sidebar plus main chat workbench, not a landing page.
- Keep the main panel vertical: transcript grows, prompt stays pinned at the
  bottom, footer/status remains stable.
- Render transcript parts as separate role-aware entries: user, assistant,
  reasoning, tool, context/source, status, and error.
- Keep reasoning and tool calls visually distinct from assistant prose.
- Make prompt state explicit: editable, submitted, streaming, stopped, errored.
- Leave room for static command suggestions later, but do not add a command
  registry before basic submit/stop/model status is solid.
- Hide decorative UI before functional UI on narrow terminals.

Brand/banner rules:

- Use `figlet-rs` only for a small `thndrs` banner in the sidebar/header or
  empty transcript state.
- Load committed `.flf` files from `src/fonts` with `FIGlet::from_content` and
  `include_str!` so the app does not depend on runtime font paths.
- Prefer a readable default font such as `src/fonts/ANSI Shadow.flf`; keep other
  fonts as optional internal assets until there is a real selector.
- Fall back to plain `thndrs` text if font parsing fails or the terminal is too
  narrow.
- Snapshot banner rendering at normal and narrow widths.

## State And Events

Start with one `App` struct and plain enums. Do not add traits until there is
more than one implementation.

Core transcript entries:

- `User`
- `Assistant`
- `Reasoning`
- `Tool`
- `Status`
- `Error`

Core messages:

- `Key`
- `Tick`
- `Submit`
- `Clear`
- `Quit`
- `Agent(AgentEvent)`

Core agent events:

- `Started`
- `AssistantDelta`
- `ReasoningDelta`
- `ToolStarted`
- `ToolOutput`
- `ToolFinished`
- `Finished`
- `Failed`

Rules:

- `update(&mut App, Msg) -> Option<Msg>` is the only mutation path.
- Assistant and reasoning deltas stay separate.
- Tool events update structured tool entries, not assistant text.
- Failed events become transcript errors and return the prompt to a usable state.

## Prompt Assembly

Alpha uses a structured prompt bundle before provider-specific lowering. Keep it
small and inspectable:

- Base identity: `thndrs` is a concise Rust/Ratatui coding harness.
- Harness policy: bounded tools, workspace containment, no raw shell access, no
  project instructions as enforcement.
- Environment: cwd/root, rounded current date/timezone, selected model, search
  mode.
- Project context: loaded `AGENTS.md` path, scope, hash, truncation state, and
  text when included.
- Tool catalog: provider-native tool schemas for local tools plus minimal text
  descriptions covering purpose, safety limits, and truncation behavior.
- Transcript tail: projected model-visible user, assistant, reasoning, and tool
  entries, excluding UI-only status rows and live-only deltas.
- User turn: current prompt text; attachments are deferred until needed.

Rules:

- Build `PromptBundle` as data, not ad hoc string concatenation.
- Lower the bundle directly into Umans messages while Umans is the only provider.
- Support `--print-prompt` as a no-network debug path for prompt assembly.
- Send a compact, stably ordered tool schema every provider turn unless Umans
  exposes explicit reusable-history or prompt-cache behavior.
- Record prompt metadata in session JSONL without storing full raw provider
  payloads by default.
- Keep edit-format instructions minimal until safe file operations exist.
- Treat `AGENTS.md` as context below harness policy and direct user/developer
  instructions.
- Include full `AGENTS.md` text only when its content hash changes and the
  provider supports history reuse; otherwise include the active size-capped
  context and always record hash/truncation metadata.

## Testing Strategy

- CLI parsing: `Cli::try_parse_from` tests.
- State updates: pure `update` tests.
- Layout geometry: pure `compute_view(Rect)` tests.
- Rendering: Ratatui `TestBackend` plus `insta` snapshots at fixed sizes.
- Provider requests: no-network request construction and stream fixture tests.
- Live Umans smoke tests: ignored/manual, gated on `UMANS_API_KEY`.
- Search/extraction: fixture tests before live web reads.
- AGENTS.md context: fixture tests for missing, root-only, oversized, nested,
  and conflicting files.

Snapshot states:

- Empty shell.
- Submitted prompt.
- Streaming assistant.
- Reasoning.
- Tool event.
- Provider error.
- Narrow layout.

## AGENTS.md Context

Treat `AGENTS.md` as repository guidance, not executable configuration. It can
influence style, workflow, commands to consider, and caveats. It cannot grant
permissions, change provider/model settings, bypass tests, disable safety
checks, reveal secrets, or override user/system/developer instructions.

Precedence:

1. System/developer/harness safety policy.
2. Current user prompt.
3. CLI/config choices owned by the user.
4. Closest applicable `AGENTS.md`.
5. Broader ancestor `AGENTS.md`.
6. Built-in defaults.

Alpha behavior:

- Discover workspace root from `--cwd`; prefer git root when available.
- Load root `AGENTS.md` if present.
- Apply a size budget and mark truncation visibly.
- Show loaded context paths before provider calls.
- Store context source metadata in the internal request shape.

Later alpha/v1 behavior:

- Support nested `AGENTS.md` once target paths are known.
- Label each loaded source with scope.
- Store path, scope, hash, and truncation state in session JSONL.

## Umans Provider

Use Umans Code as the first provider. Start with the Anthropic-compatible
Messages API because GLM 5.2 vision is documented as `/v1/messages` only and
reasoning streams arrive as explicit thinking blocks.

Provider contract:

- Base URL: `https://api.code.umans.ai`.
- Primary endpoint: `POST /v1/messages`.
- Auth header: `x-api-key: $UMANS_API_KEY`.
- Required version header: `anthropic-version: 2023-06-01`.
- Model metadata endpoint: `GET /v1/models/info`.
- Default model: `umans-coder`.
- Alternate model: `umans-glm-5.2`.

Do not introduce a generic provider trait until a second provider exists.

## Search And Extraction

Search has two lanes:

- Primary: Umans server-side web search with `X-Umans-Websearch-Provider:
native`.
- Local fallback: Lectito-backed DuckDuckGo search and deterministic article
  extraction.

Local fallback rules:

- Keep result limits small.
- Fetch only public `http`/`https` URLs.
- Reject private-network targets by default.
- Enforce redirect, timeout, content-type, and response-size limits.
- Render provider-native and local search through the same tool event shape.

## Filesystem Traversal Tools

Alpha includes structured read-only filesystem tools before write-capable tools:

- `find_files`: backed by `fd`.
- `list_searchable_files`: backed by `rg --files` or `fd --type file`.
- `search_text`: backed by `rg --json`.
- `read_file_range`: implemented in Rust.
- `summarize_text`: optional later helper using canned `awk` templates only.

Rules:

- The model sees typed tools, not raw shell command strings.
- Use `std::process::Command` argv arrays, never shell strings.
- Run from the selected workspace root.
- Reject paths escaping the root after normalization/canonicalization.
- Default to respecting ignore rules and skipping hidden files.
- Keep hidden/ignored files, symlink following, and unrestricted searches opt-in.
- Enforce timeouts, max results, max line lengths, stdout/stderr caps, and
  transcript truncation in Rust.
- Treat `rg` exit code `1` as no matches.
- Do not expose `fd --exec`, `fd --exec-batch`, `rg --pre`, arbitrary `sed`,
  arbitrary `awk`, `sed -i`, or `awk system()`.

## Sessions

Alpha persists sessions as append-only JSONL.

Session entries should include:

- Transcript events.
- Tool events.
- Provider/model metadata.
- Loaded AGENTS.md path, scope, hash, and truncation state.
- Enough file-operation metadata to audit guarded writes once those exist.

## Safe File Operations

Guarded file edits come after read-only tools and sessions.

Supported operations:

- Create file.
- Exact-range replace.
- Unified patch apply.

Rules:

- Record every write as structured transcript/tool event.
- Failed edits leave files unchanged.
- Long-running shell/process execution remains out of scope.

## File Plan

Keep the module tree small:

```text
src/cli.rs         Clap args, value enums, parse tests
src/main.rs        binary entrypoint
src/lib.rs         terminal setup and app run loop
src/app.rs         App, enums, update logic, state tests
src/ui.rs          ViewState, layout computation, render functions, render tests
src/agent.rs       fake agent stream, later Umans event adapter
src/providers/*.rs concrete Umans API client once alpha starts
src/session.rs     append-only JSONL sessions once alpha starts
src/tools.rs       read-only tools first, safe edits later
```
