# v0 / Alpha Renderer Spec

This is the implementation half of the combined v0/v1 plan. v0 replaces the
current Ratatui-owned inline shell with a direct terminal renderer. v1 stabilizes
the resulting user-facing contracts after the renderer behavior is predictable.

## Alpha Goal

Goal: make the terminal interface reliable enough that normal terminal scroll,
resize, multiline input, streaming output, and prompt accessories all cooperate.

The alpha renderer should prove:

- Completed transcript content is committed into native terminal scrollback.
- Only a small live region is redrawn for prompt, status, picker/help, and active
  streaming content.
- Mouse wheel and trackpad scrolling are left to the terminal except where a
  focused picker explicitly handles selection.
- Prompt input supports multiline editing, wrapping, cursor movement, and
  history without cursor drift.
- Resize recomputes rows and cursor position deterministically.
- Rendering is testable without needing Ratatui widgets as the source of truth.

## Direction

Use a small direct renderer, not a prompt library or Ratatui, as the owner of the
inline terminal UI.

"Small" means narrow ownership:

- terminal size and event integration;
- row layout, wrapping, padding, truncation, and ANSI style output;
- cursor placement;
- committed transcript writes;
- live-region clear/redraw;
- resize invalidation.

It does not mean a limited UX. Transcript blocks, status rows, prompt input,
file picker, help, command suggestions, tool output, and syntax highlighting
should all be richer components built on the same row model.

## Renderer Model

The renderer should convert application state into styled rows before writing to
the terminal.

Core types should stay simple:

- `CellStyle` or equivalent ANSI style metadata.
- `Span` for styled text.
- `Row` for one terminal row after wrapping/padding decisions.
- `Block` for semantic transcript, prompt, status, picker, or help content.
- `Frame` for the complete live-region render.
- `TerminalBackend` for crossterm writes, cursor movement, clearing, and size.

The row model should be independent of crossterm I/O so wrapping, padding,
truncation, cursor coordinates, and snapshots can be unit-tested.

## Layout Contract

The inline UI has two zones:

1. Committed transcript: historical content printed into terminal scrollback.
2. Live region: active rows cleared and redrawn at the bottom of the terminal.

The live region contains, from top to bottom:

- optional active transcript block while streaming;
- dynamic status/session row above the input;
- prompt input rows;
- optional picker/help/suggestion rows;
- static status row below the input.

The live region must never become an app-owned transcript viewport. Scrolling
old messages belongs to the terminal.

## Message Rendering

Message blocks should follow the Gridland/Codex/Pi direction:

- full-width backgrounds for colored blocks;
- one-cell horizontal padding inside blocks;
- vertical padding inside blocks where the block is visually grouped;
- labels above the body, not cramped into the body text;
- role-specific label colors;
- assistant, reasoning, tool, process, error, and user blocks share one wrapping
  and padding path;
- long paths, commands, URLs, and diagnostics truncate or wrap intentionally;
- syntax highlighting applies only to code fences, diffs, snippets, and useful
  command output.

## Prompt And Accessories

The prompt remains an internal model rather than a prompt-library-owned editor.

Required behavior:

- multiline insertion with `shift+enter` and `ctrl+j`;
- cursor-aware editing across wrapped and explicit newline rows;
- history navigation that preserves the current draft when appropriate;
- stable prompt indent on every visual row;
- slash-command suggestions rendered as rows, not overlays;
- file picker and `@` mentions rendered as rows, not overlays;
- `escape` closes picker/help/suggestions before it stops work or exits a mode;
- accepted file mentions can be styled distinctly in the prompt without changing
  provider-visible prompt semantics at first.

## Search And File Discovery

File discovery should prefer `fd` when available, then fall back to a bounded
Rust-native or `find` implementation. Content search should prefer `rg --json`
when available, then fall back to a bounded Rust-native or `grep` implementation.

Fallback behavior must be visible in diagnostics and tests. Missing `fd`/`rg`
should degrade capability, not break prompt/file-picker workflows.

## Terminal Backend

The backend should use crossterm directly for inline mode:

- raw mode setup/cleanup;
- terminal size reads and resize events;
- cursor hide/show;
- clear live-region rows;
- move cursor to the computed prompt cursor coordinate;
- write committed transcript rows once;
- write live-region rows repeatedly.

Ratatui may remain temporarily for existing tests or alternate-screen
experiments, but it is not the source of truth for inline rendering.

## Testing

Required checks:

- row wrapping and truncation tests at narrow, normal, and wide widths;
- cursor coordinate tests for single-line, wrapped, multiline, and indented
  prompts;
- render snapshots for empty startup, active prompt, multiline prompt,
  streaming assistant, reasoning, tool output, errors, file picker, help, and
  narrow width;
- resize tests that shrink and grow width without losing prompt content;
- smoke test that committed transcript output remains scrollback-friendly;
- fallback tests for missing `fd` and missing `rg`.

## Alpha Exit Criteria

- No known terminal cleanup bugs.
- No known prompt cursor bugs for ASCII and common multibyte input.
- Wheel/trackpad scrolling scrolls terminal history, not the prompt input.
- Narrow, normal, and wide terminal screenshots are coherent after resize.
- File picker, help, and command suggestions do not use fragile overlays.
- Existing non-UI provider/tool/session behavior still passes tests.

## Deferred To v1

- Stable config file contract.
- Stable session inspect/export command contract.
- Read-only LSP-backed code intelligence.
- Skill engine.
- Agent self-knowledge/introspection contract.
- Packaging and release candidate guarantees.
