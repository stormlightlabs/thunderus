# v1 Spec

v1 defines the supported user-facing contract for `thndrs`: stable CLI/config
behavior, durable session inspection, documented AGENTS.md semantics, recoverable
file operations, bounded shell/process execution, read-only code intelligence,
packaging, release notes, and a release candidate checklist.

## Release Goal

Goal: define the supported user-facing contract and make the harness predictable
enough to install and use repeatedly.

Required:

- Stable CLI flags, environment variables, config file keys, and session format.
- Documented AGENTS.md precedence, scoping, size caps, and session audit behavior.
- `--help` documents default model, search modes, config path, and session path.
- Config file support with CLI/env overrides and clear precedence.
- File write/edit behavior is documented, bounded, and recoverable.
- Shell/process manager behavior is documented, bounded, recoverable, and clear
  that commands run as local processes with the user's permissions.
- Prompt fragments and `read_url` have stable documented behavior.
- Read-only LSP-backed code intelligence works where a language server exists.
- Session inspect/export can read sessions without opening the TUI.
- Release notes follow a changelog format.
- Packaging supports at least `cargo install`.
- CI runs formatting, clippy, unit tests, snapshot tests, and no-network provider
  fixture tests.
- Upgrade behavior is documented for alpha session/config changes.

## Public Contract

For this CLI app, v1 public contract includes:

- CLI flags and subcommands.
- Environment variables.
- Config file path and keys.
- Session JSONL schema.
- Tool names, inputs, and safety limits.
- AGENTS.md precedence and scoping.
- Prompt-fragment assembly rules that affect observable behavior.
- `read_url` safety limits and output shape.
- Shell/process tool names, inputs, outputs, limits, transcript/audit behavior,
  and local-process security model.
- LSP tool names, inputs, outputs, and no-server fallback behavior.
- Exit codes for non-TUI commands.
- Documented install and upgrade workflow.

## CLI And Config

v1 may add non-TUI `inspect` and `export` commands once sessions exist.

Config precedence:

1. CLI flags.
2. Environment variables.
3. Config file.
4. Built-in defaults.

Config should cover:

- Default model.
- Web search mode.
- Session path.
- Tick rate.
- Default workspace behavior.

Secrets stay out of config examples. `UMANS_API_KEY` remains the secret path.

## Session Inspect And Export

Non-TUI commands should output JSON or JSONL and include:

- Transcript entries.
- Provider/model metadata.
- Tool events.
- Loaded AGENTS.md paths, scopes, hashes, and truncation state.
- File-operation audit metadata.

Inspect/export must not leak API keys or machine-specific transient data.

## AGENTS.md Contract

Document:

- Precedence: harness policy, user prompt, CLI/config, nearest AGENTS.md,
  broader AGENTS.md, defaults.
- Root and nested file scoping.
- Size caps and truncation behavior.
- Session audit metadata.
- Authoring guidance and common smells: context bloat, lint leakage,
  tool-specific skill leakage, and conflicting instructions.

Repository instructions cannot grant permissions, change provider/model settings,
bypass tests, disable safety checks, reveal secrets, or override user/system
instructions.

## File Operations Contract

Supported write operations:

- Create file.
- Exact-range replace.
- Unified patch apply.

Required behavior:

- All writes are recorded as structured transcript/tool events.
- Failed edits leave files unchanged.
- File path, operation type, and result are visible.
- User can recover by inspecting session events and normal `git diff`.

## Shell And Process Contract

v1 should stabilize the v0 shell/process manager instead of expanding it into a
general automation system.

Required behavior:

- Commands run from an explicit working directory.
- Active commands can be listed, cancelled, and inspected.
- Persistent background processes can be started, listed, inspected, and
  stopped through the same transcripted process registry.
- Output streaming is bounded and cannot make the TUI unresponsive.
- Transcript events include command, working directory, timing, exit status,
  timeout/cancellation state, and output summary.
- Shell commands run with the permissions of the `thndrs` process. The CLI must
  document that this is not a sandbox and that untrusted or unattended work
  belongs in an external OS/container/VM or policy sandbox.
- Shell usage should be discouraged by prompt/tool guidance when narrower tools
  fit file search, file reads, edits, URL reads, or search.
- Destructive commands are handled through model-facing guidance, transcript
  visibility, and normal user review of diffs/output, not an in-process
  approval classifier.
- Known secrets are redacted from displayed and recorded command output where
  deterministic redaction is possible.

Out of scope:

- Remote shell sessions.
- Cron/scheduler behavior.
- Package-manager abstraction.
- Shell-command permission parsing or approval prompts presented as a security
  boundary.

## LSP And Code Intelligence

v1 should add read-only LSP-backed tools when they are clearly better than plain
file search.

Supported operations:

- Document symbols.
- Workspace symbols.
- Go to definition.
- Find references.
- Hover.
- Find implementations where the server supports it.

Required behavior:

- Never edit files through LSP.
- Prefer existing installed language servers and degrade clearly when none is
  available.
- Keep startup and indexing bounded with visible diagnostics.
- Record LSP calls as structured transcript/tool events.
- Preserve plain file search as the fallback path.

Out of scope:

- Code actions.
- Automatic refactors.
- Untracked LSP server processes that outlive the session.
- Project-wide task management.

## Additional v1 Fits

These fit v1 if they remain narrow and reuse the session/tool contracts:

- Session title generation from transcript metadata.
- Transcript chunk summaries for long sessions.
- Session search once persistence exists.
- Review and security-review prompt fragments that operate on explicit diffs or
  session events.
- Deterministic write-tool validation and recoverable edit events.

## Explicit Non-goals

- No plan mode.
- No task management or todo system.
- No subagent or multi-agent orchestration.

## Release Candidate Bar

- No known data-loss bugs.
- No known terminal cleanup bugs.
- No known secret leakage in logs, snapshots, sessions, or errors.
- All non-network tests pass from a clean checkout.
- Manual Umans smoke test passes with `UMANS_API_KEY`.
- Packaging smoke test passes from a local package artifact.
- v1 known limitations are documented.
